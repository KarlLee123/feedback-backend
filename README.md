# 客户反馈整理工具（第一版）

## 1. 项目介绍

这是一个用于整理客户评价/客户反馈的小工具。

用户把一大段客户反馈文本贴进输入框后，系统会自动整理出 4 类结果：

- 大家最常夸什么
- 大家最常吐槽什么
- 最常出现的问题
- 宣传时可以强调什么

这套结果不是固定写死的，而是通过 AI（人工智能大模型）分析原始反馈后生成的。

---

## 2. 当前版本已经实现的功能

### 前端页面
- 输入页
- 结果页
- 历史记录页

### 后端功能
- 提交客户反馈文本
- 调用千问 AI（阿里云的大模型服务）分析文本
- 返回固定四类整理结果
- 保存分析记录到 MySQL（关系型数据库）
- 查询历史记录列表
- 查询历史记录详情
- 删除历史记录
- 统一异常处理（后端报错时返回统一格式的错误信息）

## 5. 当前接口说明

### 1）分析客户反馈
- 请求地址：`POST /api/analyze`
- 作用：提交一段客户反馈，返回四类整理结果，同时保存历史记录

#### 请求体示例
```json
{
  "content": "很多用户反馈客服态度很好，回复也比较及时，发货速度快。但是也有一些用户提到包装一般，尺码偏小，物流偶尔偏慢。还有人说整体购物体验不错。"
}
```

#### 返回体示例

```json
{
  "goodPoints": [
    "客服态度好",
    "回复及时",
    "发货速度快",
    "购物体验不错"
  ],
  "badPoints": [
    "包装一般",
    "尺码偏小",
    "物流偶尔偏慢"
  ],
  "commonProblems": [
    "尺码偏小",
    "物流偏慢"
  ],
  "marketingHighlights": [
    "客服响应快",
    "发货效率高",
    "整体体验较好"
  ]
}
```

---

### 2）查询历史记录列表

* 请求地址：`GET /api/records`
* 作用：查询所有历史分析记录

---

### 3）查询历史记录详情

* 请求地址：`GET /api/records/{id}`
* 作用：根据记录 id 查询某一条分析详情

---

### 4）删除历史记录

* 请求地址：`DELETE /api/records/{id}`
* 作用：删除指定 id 的历史记录

## 6. 数据库设计

当前第一版只使用一张主表：

### 表名

`feedback_record`

### 字段说明

* `id`：主键
* `raw_text`：用户原始输入的客户反馈
* `good_points`：最常夸什么
* `bad_points`：最常吐槽什么
* `common_problems`：最常出现的问题
* `marketing_highlights`：宣传时可以强调什么
* `created_at`：创建时间

## 7. AI 在项目中的作用

这个项目真正的核心价值，不是页面，也不是数据库，而是 AI（人工智能模型）分析能力。

如果没有 AI，这个项目只能做到：

* 接收文本
* 返回固定假数据
* 保存记录

接入千问 AI（阿里云的大模型服务）之后，系统才能根据不同的原始反馈内容，动态生成不同的整理结果。

也就是说：

* 工程部分负责“让系统能跑起来”
* AI 部分负责“让系统有实际价值”

AI 在当前项目中的主要作用是：

* 理解自然语言（用户写的评价、吐槽、反馈）
* 提炼正向评价
* 提炼负向吐槽
* 归纳常见问题
* 提炼可宣传的卖点

## 8. 如何启动项目

### 后端启动步骤

1. 打开 `feedback-backend`
2. 配置 `application.yml`
3. 确保 MySQL（关系型数据库）已启动
4. 确保数据库已创建
5. 运行 `FeedbackBackendApplication`

### 前端启动步骤

1. 打开 `feedback-frontend`
2. 安装依赖：

   ```bash
   npm install
   ```
3. 启动前端：

   ```bash
   npm run dev
   ```

## 10. 异常处理说明

项目已经接入了全局异常处理（统一拦截后端异常并返回固定 JSON 格式）。

当前异常返回格式示例：

```json
{
  "message": "记录不存在，id=999999",
  "timestamp": "2026-03-15T18:00:00"
}
```

这样做的好处是：

* 前端更容易显示错误信息
* 接口报错格式更统一
* 不会直接把难看的默认报错页面返回给前端

## 11. 当前版本限制

这是第一版 MVP（最小可行产品版本），目前还有这些限制：

* 没有登录注册
* 没有用户系统
* 没有文件上传
* 没有分页
* 没有批量管理历史记录
* 结果页和历史详情页仍然比较简单
* AI 输出仍然依赖提示词质量，后续还可以继续优化
